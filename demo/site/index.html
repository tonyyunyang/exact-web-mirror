Five of the things this page needs come from somewhere a naive download will not follow. Nothing here is exotic — it is how ordinary sites are built now. Scroll, and each section will tell you whether its resource actually arrived.

  1. 01 checking…

    Stylesheet on another origin

    Every rule that gives this page a layout, a scale, and a color is served from a second origin. Keep the HTML and lose the stylesheet and you keep the words and lose the design.

    If this reads as plain text on a dark page, the stylesheet did not arrive.

  2. 02 checking…

    A module that imports a chunk by hash

    The script tag points at one module. That module imports a second file whose name contains a build hash. The chunk's URL appears in no HTML you could scan and rewrite — it is assembled while the page runs.

    These status lights are driven by that chunk. Dim lights mean it never loaded.

  3. 03 checking…

    Video fetched in byte ranges

    Browsers do not download a video in one piece. They ask for byte ranges and get partial responses back. Recorders that store what the browser received end up with a stack of fragments and no file.

  4. 04 checking…

    An image whose address is built at runtime

    This one is not in the markup at all. A script joins a base address to a file name and sets the result on an element after the page loads. There is no string to find and no link to follow — you have to run the page to learn the address.

  5. 05 checking…

    A shader that has to keep running

    The colour field behind the title is a WebGL fragment shader — GLSL source compiled by the browser and redrawn every frame. It is the effect a lot of modern landing pages open with, and there is no image of it anywhere to download. A screenshot of it is not it. The only way to still have this later is to still have the program that draws it.

    Look up. If the colours are drifting, the shader is compiled and running.
